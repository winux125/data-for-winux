# Аудит по ТЗ Datathon 26

Дата проверки: 18 октября 2026, Asia/Qyzylorda. Целевая VM — `forte-vision-50`, первоначальная организация NVIDIA с предоставленными $50, A100 SXM4 80 GB, $1.656/час по каталогу при создании. Адрес: https://154.54.100.194.sslip.io/app.

## Главный вывод

Фронтенд, API, очередь, локальный inference и HTTPS объединены. **Полную готовность для автоматической проверки жюри заявлять нельзя:** исходный RAG запрещает публиковать результаты всех восьми карточек до человеческой проверки и активации. Этот запрет сохранён по прямому требованию не менять JEPA/RAG и их логику. `failed` в таком случае означает необработанное видео по критериям жюри.

`production_active=false` — не замечание аудитора поверх модели, а собственная политика готового входящего RAG. Обвязка не меняет её на true, не повышает `insufficient` до нарушения, не публикует заблокированные решения и не заменяет положительное сомнение отрицательным вердиктом.

## Целостность и границы изменений

Проверка ZIP и распакованных файлов выполнена локально и на целевой VM: **66 файлов JEPA и 241 файл RAG совпадают побайтно**. Отчёт — приватный `data/input-integrity.json`. Веса, PCA/SVM, локализатор, пороги, карточки, промпты, генерация, правила и исходные конфигурации не переписаны.

Используются `JepaModel.predict()` и `LegalRAGRuntime.analyze()`. Старые адаптерные обходы, предварительные категории по `insufficient`, замена генерации RAG и приватные вызовы JEPA удалены из рабочего маршрута. Настройки поиска/генерации берутся из исходного `configs/cuda.json`. Идентификаторы моделей разрешаются в локальные snapshots тех же revisions: без такой адаптации Transformers 4.57.3 пытается запросить metadata даже с `local_files_only`. Это настройка размещения весов, а не замена модели или алгоритма.

Визуальный адаптер Qwen8B — отдельный компонент связки, поскольку JEPA возвращает бинарный результат/примерный момент, а RAG принимает факты, а не видео. Его оптимизация patch projection не применяется к JEPA или RAG. Экспериментальная 32B-модель не используется; соответствующие процессы остановлены.

## Обязательный сценарий и API

| Требование ТЗ | Фактическое состояние |
|---|---|
| Рабочий frontend и backend | Forte-vision и FastAPI доступны на одном HTTPS-домене, запускаются автоматически |
| Загрузка MOV | UI + multipart API, реальная отправка файла, единый лимит 128 МиБ |
| Отображение обработки | XHR-передача, затем статус задания; без выдуманного процента inference |
| Два вердикта | Только `violation/no_violation` при `done`; ошибки без вердикта |
| Несколько событий | Контракт поддерживает список; синтетический интеграционный тест проверяет два разных события |
| Тип события | Из карточки исходного RAG; семантическое качество на новых видео не установлено |
| Таймкод | PTS реального декодированного кадра; выбирается адаптером из предоставленных кадров |
| Доказательства | 1–3 JPEG/base64 из исходного видео, без генерации изображения |
| Понятное обоснование | Исходное объяснение RAG; неподтверждённое решение не публикуется |
| Нормативный источник | Название, точный пункт при наличии, URL и цитата, полученные от RAG |
| API жюри | POST `/api/v1/analyze` → job_id; GET `/api/v1/jobs/{job_id}` |
| Авторизация | `X-API-Key`, запросы без правильного ключа отклоняются |
| Максимум 5 минут | Серверный дедлайн 285 с; успешность всех положительных роликов за этот срок не подтверждена |
| Локальность | Все модели в VM; worker offline и с `PrivateNetwork=true` |
| Переносимость | Код, пакеты, weights/cache/index переносятся совместно; сеть нужна на этапе установки |
| Отсутствие аудио/идентификации | Используется только видеопоток; нет распознавания личности или биометрического сопоставления |
| Статичный адрес | Привязан к IP VM; перезапуск приложений не меняет URL, удаление VM может изменить его |
| Полноценная выдача нарушений | **Блокер: исходные карточки RAG не разрешают публикацию** |

## Аудит forte-vision

Сохранены фирменное оформление, адаптивные экраны и интерфейс разработчика. Подключён существующий API-клиент, который отправляет файл и получает реальные статусы; результаты модели не подменяются примерами.

Исправлены интеграционные расхождения:

- Лимит 250 МБ заменён на 128 МиБ в проверке, подсказках и переводах.
- Убраны устаревшие утверждения «пока только фронтенд» и «сервер подключается отдельно». Указаны текущий сервер, API-ключ и возможность оставить адрес пустым.
- Ошибки RAG/worker объясняются на RU/KK/EN. Ошибка не выглядит успешной проверкой.
- Правило с отсутствующим пунктом передаётся без null: клиент принимает такой контракт.
- Исправлено форматирование длительности на казахском: различия ICU между Node и Chromium вызывали hydration mismatch.
- Из общего layout убран необязательный баннер настроек браузера: он перекрывал кнопки проверки. Страница информации о данных сохранена.
- Исправлен контраст пояснения в тёмной теме. Проверка checkbox кликает по видимой связанной подписи, поскольку React Aria намеренно скрывает нативный input.
- Исправлены lint-замечания: внутренний переход через Link, неиспользуемая директива. Для намеренной синхронизации browser state после SSR оставлены точечные комментарии; правила fake React/CommonJS test harness отделены от прикладного кода.
- E2E восстановления задания учитывает сохранение hash-маршрута и открывает историю перед выбором восстановленной записи.
- Очистка исходников охватывает также задания, истёкшие в очереди до запуска worker. Статус ошибки при этом сохраняется до TTL; чистый вердикт не подставляется.

Фронтенд использует локальные шрифты и ассеты. В проверке пустого рабочего пространства внешних запросов не обнаружено. Это наблюдение о проверенных экранах, а не доказательство отсутствия любого возможного внешнего запроса во всём браузере пользователя. Ввод другого API-адреса остаётся явной пользовательской настройкой; для сдачи используется API на том же домене.

Необязательные возможности исходного фронтенда — демонстрационные примеры, локальная история, экспорт, темы, языки — не используются как доказательство выполнения ML-требований. Ранее созданная временная vanilla-страница исключена из маршрутизации и production-пакета.

## Нормативная база и категории

Основной источник карточек: [Правила осуществления кассовых операций и операций по инкассации, регистрация V1900019680](https://adilet.zan.kz/rus/docs/V1900019680). В пакете сохранены 54 нормативных снимка, источники, хэши и структура пунктов. Пять основных актов ранее повторно проверены через официальный content API Әділет, содержимое совпало; приватный отчёт `data/source_revalidation.json`. Это проверка текста, а не подтверждение юридической интерпретации каждой карточки.

| Пункты правил №231 | Категория исходного RAG | Предел наблюдения |
|---|---|---|
| 12 | Личные вещи работника в кассовом узле | Нужны видимый объект, роль и контекст исключений; нельзя угадывать назначение/принадлежность |
| 20 | Приём/пересчёт не в присутствии клиента | Клиент может находиться вне обзора; отсутствие нельзя выводить из узкого кадра |
| 20 | Принятые наличные вне закрывающегося устройства | Требуется наблюдение и контекст операции |
| 22 | Уход до окончания обслуживания | Поворот или наклон не равны уходу; завершённость обслуживания может быть неизвестна |
| 25 | Вскрытие повреждённой инкассаторской сумки | Нужны видимые повреждение, действие и контекст присутствия инкассатора |
| 31/32 | Выдача без требуемого пересчёта | По разреженным кадрам адаптер не подтверждает отсутствие действия на всём интервале |
| 42 | Процедура пересчёта/сортировки/упаковки | Обычное обслуживание не доказывает применимость именно этого пункта |

Все карточки сейчас черновые. `/api/v1/rules` экспортирует исходные `human_reviewed/production_active`, без собственной пометки «включено». Другие найденные нормы также не обходят исходный publication gate. Неизвестная дата события не заменяется датой загрузки. Доступа к АБИС, проводкам, балансам и внутренним журналам нет; соответствующие выводы не заявляются.

## Проверки и доказательность

- 18 тестов обвязки прошли на целевой VM: авторизация, очередь, размер, ошибки, восстановление, дедлайн, JPEG/PTS, несколько событий, передача фактов и сохранение публикационного запрета.
- Все 104 исходных теста RAG прошли. Это структурные тесты, включая fake/template backends, а не оценка семантики нейронной модели.
- Production-сборка, typecheck, все 106 frontend unit tests и lint прошли. **Все 74 браузерных теста Chromium/WebKit прошли за 1.1 минуты** в заключительном полном прогоне; приватный лог `data/frontend-checks-complete.log`. Первые неуспешные прогоны сохранены отдельно и не засчитываются как прошедшие.
- Все шесть проверок desktop/mobile и RU/KK/EN прошли без ошибок JS, переполнения и внешних запросов в проверенном рабочем пространстве; отчёт `data/frontend-browser-checks.json`.
- Реальный браузерный сценарий с настоящим MOV и текущим ключом прошёл без ошибок JS: POST=202, результат `no_violation` показан интерфейсом. Приватный отчёт `data/browser-api-smoke.json`. Это отдельная проверка UI/API, а не независимая оценка модели.
- Реальный публичный smoke-прогон на обучающем MOV с отрицательной меткой дал `done/no_violation` за 29.265 с, включая загрузку и опрос. Отчёты последующих прогонов — приватный `data/public-smoke-stock/`.
- Второй реальный MOV с положительной меткой завершился через 254.704 с с `failed/evidence_insufficient`, без выдуманного чистого вердикта. Для жюри это необработанный ролик; успешный положительный сценарий на реальных данных не подтверждён.
- Отдельные синтетические ответы с положительными событиями проверяют только API/UI. Они не выдаются за реальную готовность положительного анализа.

Предварительный браузерный прогон обнаружил дефекты баннера и контраста, а также проблемы самих тестов: клик по намеренно скрытому input, ожидание другого маршрута после reload, замер до готовности WebKit и зависимость ошибочного MOV от поддержки кодека. Тесты теперь используют видимый checkbox, ожидают отображения и подают заведомо повреждённый синтетический файл. WebKit в тестовом контейнере также не имел системного CA bundle: это исправлено установкой ca-certificates, без отключения проверки TLS. Полные логи и screenshots тестов остаются приватными.

## Что не подтверждено и что остаётся

1. **Публикация положительных решений:** заблокирована исходным RAG. Для изменения потребуется работа владельца этого компонента; в рамках текущего запрета такие изменения не выполняются.
2. **SLA для всех видео:** дедлайн соблюдается как предел ожидания, но исходный полный RAG может расходовать его на несколько нормативных кандидатов. Истечение времени засчитывается как необработанное видео.
3. **Независимое качество:** JEPA-FULL обучена на всех 40 уникальных роликах. Прогоны на них не являются независимым тестом. Старый F1 0.857 с исследовательских изображений не заявляется метрикой сервиса.
4. **Новый ракурс и новые категории:** отдельно не подтверждены. Разреженные окна могут пропускать короткие события. Несколько выходных событий в контрактном тесте не доказывают качество их обнаружения.
5. **Наблюдения Qwen:** корректная JSON-структура не доказывает истинность фактов. Неоднозначность и невидимые условия могут оставить ролик без итогового вердикта.
6. **Одна GPU-очередь:** параллельные принятые задания делят общий ресурс; очередь ограничена, возможны 429 и тайм-аут.
7. **Предыдущая VM:** содержит другой проект и не удалена; её тарификация продолжается. Наши API/worker/Caddy остановлены и отключены из автозапуска, временный контейнер фронтенда остановлен. Обычная остановка с сохранением данных для её типа не поддерживается; удаление всей VM может уничтожить другие данные. Новый URL обслуживается первоначальным аккаунтом с $50.

Рабочая инфраструктура, пройденные структурные тесты и один успешный отрицательный ролик не означают полного выполнения ТЗ. Блокер публикации и независимое качество должны быть решены до объявления сервиса готовым к оценке жюри.
