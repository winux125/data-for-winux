Этот документ сохраняет описание v3. Активен JEPA-LGBM-FULL и обновление Qwen/RAG [v3.2](QWEN_PROMPTS_V3_2_2026-10-18.md); актуальная сводка моделей и запуска — [README RAG/Qwen](LEGAL_RAG_QWEN_README.md).

Рабочий UI: https://forte26.vercel.app/app. GPU API:
https://154.54.100.194.sslip.io/docs. Ключи в исходники и документ не включены.
Коммитов и push не выполнялось.

## Активная схема v3: структурные источники

1. `JEPA-FULL.predict()` обрабатывает видео и даёт бинарный сигнал/момент.
2. Отрицательный класс: `done/no_violation`, без декодирования кадров для Qwen,
   наблюдений и RAG. Это ответ классификатора, не доказательство отсутствия
   каждого возможного нарушения. Ложные отрицательные JEPA остаются риском.
3. Положительный класс: обзор до 24 кадров и окно до 7 кадров возле момента JEPA.
   Кадры исходные, время по PTS. Qwen3-VL-8B локально описывает видимые действия,
   до трёх фактов на эпизод. Ненаблюдаемые условия не требуется заполнять.
4. `LegalRAGRuntime.review()` принимает только факты, без метки/оценки JEPA.
   Гибридный поиск BGE-M3 + BM25/RRF работает по тем же структурным единицам
   и уровням корпуса. В поисковые запросы входят известные наблюдения с
   сохранением отрицаний; неизвестные условия не засоряют ранжирование.
5. Если карточка содержит наблюдаемый признак действия и не опровергается
   известными условиями/исключениями, собирается полный нормативный пакет.
   Неизвестные условия сохраняются; отсутствие окончательного правового
   подтверждения не становится ошибкой обработки.
6. Если карточка не подошла, Qwen выбирает пункт из структурного гибридного
   поиска: сначала core, затем operational, без смешения их оценок. Передаются
   целые родительские пункты, связанные положения, определения и исключения.
   Модель возвращает ID пункта, ID строки требования и ссылки на факты.
   Код извлекает точную цитату из источника: свободное переписывание не нужно.
   Выдуманные ID и ссылки на чужие/неизвестные факты отклоняются.
   Общие определения, нерелевантные и неподтверждённые по действию пункты не
   должны становиться выбранным требованием. Это условие промпта, содержательную
   точность которого ещё нужно оценивать отдельно.
   Если ни один кандидат не принят, правила кассовых операций цитируются
   на уровне документа только как контекст, а не как доказанный нарушенный
   пункт. Это явно отмечено в тексте и `source_relation=context_only`.
7. Qwen3-VL-4B локально генерирует короткую условную связь с источником.
   Наблюдения вставляются из проверенного входа, цитаты/ссылки — из корпуса.
   При невалидной генерации используется явно учтённый `template_fallback`.
8. API отдаёт `violation` в смысле ТЗ: признаки возможных нарушений для человека.
   `legal_decision` и неизвестные условия отдельно сохраняют предел обоснования.
   Реальные сбои чтения видео, кадров или моделей по-прежнему дают `failed`.

До трёх выбранных эпизодов; приоритет у явно наблюдаемых действий и момента
JEPA. Ограничения выборки и локализатора не позволяют обещать нахождение всех
событий или непрерывную видимость операции. Нового обучения не было.

Рабочий лимит текстовой Qwen увеличен до 8192 токенов, визуальной остаётся
24576. Это серверные бюджеты, не нативные пределы моделей. Обе модели работают
в BF16, квантизация не добавлялась. Из пакета убраны повторяющиеся названия
документов и повтор основного пункта; нормативный текст не обрезается.
Перед вызовом учитывается размер подготовленного запроса. Если альтернативные
родители не помещаются, они пропускаются целиком с записью причины в аудите.

Интерфейс сохраняет quote при разборе API и показывает полный текст пункта,
путь главы/раздела и раскрываемые связанные положения. React отображает текст
без выполнения HTML. Старые локально сохранённые результаты, где прежний
парсер уже выкинул цитату, могут остаться без неё до повторного получения.

## Два разных контракта

`analyze()` / `legal_rag.output.v1` сохраняет формальное применение нормы.
`violation_supported` требует известных обязательных условий и исключений.
`publishable_assessments()` не пропускает `insufficient` даже с allowed=true.

`review()` / `legal_rag.review.v1` возвращает отдельные `review_findings` с
`finding_kind=possible_indication`, `human_review_required=true` и явной
политикой `possible_indications`. Эти результаты не выдают неизвестные факты
за подтверждённые и не переписывают формальные решения.

В событии API:

- `source_relation=candidate_clause`: пункт — кандидат для проверки; условия
  применения могут оставаться неизвестными.
- `source_relation=context_only`: нормативный документ даёт общий контекст;
  конкретный нарушенный пункт не установлен, поле section отсутствует.
- `legal_decision`: исходное формальное состояние, например insufficient,
  либо not_established для документа-контекста.
- `unknown_conditions`: что ещё нужно выяснить человеку.
- `evidence_frames`: 1–3 исходных JPEG с PTS, без генерации изображения.

Тип `Эпизод риска для проверки` — сигнал модели для просмотра, не заявление,
что показанное обычное действие само по себе запрещено. Показатель завершённых
бинарных ответов нельзя считать точностью юридических обоснований.

## Источники и размещение

Исходные `JEPA-FULL/` (66 файлов) и `ForteBank-Legal-RAG-2026-10-18/` (241 файл)
сохранены побайтно. Рабочий RAG находится в `releases/legal-rag-mvp-v1/`,
накладываемые исходники — `patches/legal-rag-mvp-v1/`. Имя директории сохранено;
сервис использует режим `possible_indications` из `config/analysis-policy.json`,
а реализация выбора источников обновлена до v3.

Настройки моделей/поиска: `config/rag-mvp.json`, наблюдений: `config/observer.json`.
Карточки не получили выдуманных подписей: `human_reviewed/production_active`
остаются false. Формальная публикационная политика evidence_assisted и
review-политика possible_indications различаются явно.

Все модели локальны в существующей A100 VM. `PrivateNetwork=true`, offline
Transformers/HF сохранены. Qdrant, новые документы и реранкер не добавлялись:
измеренный поиск занимал менее секунды, а основной отказ происходил после него.

- Frontend: typecheck, 108 unit, lint, 74 Chromium/WebKit E2E. UI отображает «Обнаружены признаки возможных нарушений».

- Шесть одинаковых видео проверяются до/после. Это train-smoke: JEPA-FULL

## Установка и откат

Из корня проекта после размещения исходных пакетов, зависимостей и весов:

```bash
.venv/bin/python scripts/install_rag_mvp.py
PYTHONPATH="$PWD/releases/legal-rag-mvp-v1:$PWD" .venv/bin/python -m unittest discover -s releases/legal-rag-mvp-v1/legal_rag/tests -t releases/legal-rag-mvp-v1
PYTHONPATH="$PWD/releases/legal-rag-mvp-v1:$PWD" .venv/bin/python -m pytest tests -q
```

Installer создаёт новую рабочую копию из исходного пакета и патча. Если каталог
уже существует, он проверяет совпадение, а не молча переписывает работающий код.
Обновление существующей версии выполняют после резервной копии и без заданий
в очереди/обработке. На этой VM откат v3: `data/takeover-pre-structural-sources-v3/`;
старый frontend сохранён тегом `forte-vision:pre-structural-v3`. Для отката к v2
восстановить сохранённые файлы и перезапустить свободный worker. Старые копии
v1 также сохранены. Старую дополнительную VM не изменяли и не удаляли.
