# API и нормативные объяснения v3.1

История предыдущего обновления. Текущая версия — [Qwen v3.2](QWEN_PROMPTS_V3_2_2026-10-18.md); контракт API v3.1 сохранён.

18 октября 2026, Asia/Qyzylorda. **Развёрнута на существующей A100 VM**, build `676ac1704d9cf4b7`. Проверены реальные задания через публичный API и два одновременных запроса; сервис готов принимать задания.

## Изменения

- Оба маршрута отправки и опроса задания имеют явные response models. OpenAPI описывает `processing / done / failed`, два успешных вердикта и массив `violations`. Ошибка не может содержать чистый вердикт.
- В обязательный `description` добавляются название источника, точный пункт при наличии и URL. Дополнительные поля `rule.quote` и `rule.context` сохраняют полные тексты.
- `Accept-Encoding: gzip` включает сжатие ответа без изменения JSON или качества JPEG. На сохранённом ответе v3 размер снизился с 567 211 до 405 512 байт; это измерение размера, не гарантированное ускорение сети.
- Визуальная Qwen возвращает функциональную роль. Наблюдение клиента больше не получает роль кассира автоматически.
- Повторные наблюдения объединяются до нормативных вызовов. Близкие моменты одной роли с одинаковым основным действием могут объединяться; контекст и ссылки на кадры сохраняются. Эта эвристика не определяет биометрическую личность.
- Жёсткий лимит в три выбранных эпизода снят. Текущие два прохода по-прежнему дают максимум четыре кандидата. API сортирует события по времени; отдельного «основного нарушения» нет.
- `type` описывает наблюдаемое действие, а не номер выбранного пункта. Неподтверждённый тип действия не выдумывается.
- Нормы сопровождения, инкассации и явно противоположного направления операции проверяются на соответствие наблюдаемому контексту перед нейронным выбором. Это целевые ограничения области применения, а не универсальный юридический анализ.
- Constrained JSON допускает кириллицу; EOS согласован с токенизатором. Альтернативный stop token модели не должен обрывать JSON внутри строки.
- Генерация выбора источника и объяснения использует ограниченный JSON с проверкой ID и привязки к фактам. Валидатор различает условный вопрос и категорическое обвинение; код добавляет источники сам.

Гибридный BM25/BGE-M3 поиск, RRF по уровням, структурные parent–child единицы, полные нормативные пакеты и исходные веса сохраняются. Qdrant, reranker и новые документы не добавлялись.

## Граница с экспериментом v4

Пробовали дополнительную оценку `possible_risk / routine / unclear` в первой Qwen. Она стала вторым фильтром после JEPA и пропустила положительные учебные видео. Краткий контекст правил восстановил один из двух пропусков, но второй остался необработанным. Плотные oracle-окна, сокращённый промпт и native-video проба не дали достаточного подтверждения улучшения.

**Этот фильтр не включается в v3.1.** Код прототипа сохранён вне рабочего репозитория: `experiments/grounded_episodes_v4_candidate/` в общем workspace. Нельзя считать неудачные экспериментальные результаты метриками v3.1 или успешным улучшением.

JEPA-LGBM остаётся первым классификатором. Его отрицательный класс пропускает Qwen/RAG. Для положительного видео Qwen извлекает наблюдения, RAG формирует материал для проверки человеком. Наличие материала для проверки не означает доказанное юридическое нарушение. Возможность публикации обычного действия как контекста положительного сигнала классификатора пока полностью не устранена; качество визуальных фактов и юридической связи требует отдельной оценки.

## Проверка

До видео-прогона проходят **55 backend и 135 RAG тестов**. Уменьшение backend-счётчика относительно экспериментальных 58 связано с заменой тестов отклонённого второго классификатора тестами выбранной архитектуры; это не скрытые падающие тесты.

Полный smoke использует шесть уже разрешённых видео: два отрицательных и четыре положительных, включая длинные записи. Детектор обучен на всех 40 исходных видео; это проверка работоспособности, а не независимый test, CV или новая оценка F1. Качество таймкодов, ролей, фактов и нормативной интерпретации нельзя доказать совпадением бинарных меток.

Перед заменой production проверяются отсутствие активной очереди, хэши исходной версии, завершённый smoke и время ответа. Сохраняется резервная копия заменяемых файлов; при неуспешном запуске предусмотрен откат. Веса, карточки и подписи проверяющих не переписываются. `PrivateNetwork=true` worker сохраняется.

### Развёртывание

Перед заменой проверены хэши прежнего production и пустая очередь. Создана резервная копия `data/pre-source-contracts-v3.1/`. После копирования хэш backend совпал с проверенной staging-версией; 55 backend-тестов повторно прошли на активных файлах. Worker загрузил модели, `/readyz=200`, `PrivateNetwork=yes`.

Публичная проверка контракта: `/healthz=200`, `/readyz=200`; запросы без ключа и с неверным ключом — 401; неизвестное задание с ключом — 404; POST с ключом без файла — 422. OpenAPI содержит discriminator `done / processing / failed`.

Эти восемь API-заданий подтверждают выполнение проверенных сценариев. Они не доказывают правильность каждого из одиннадцати выданных событий, точность их границ, правовую квалификацию или качество на новых видео. Старые задания не пересчитываются: новую версию видно после повторной загрузки. Коммиты и push не выполняются.
