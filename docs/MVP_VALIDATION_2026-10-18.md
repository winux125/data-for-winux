## Результат

На существующем forte-vision-50 развёрнута политика `possible_indications`.
Новые VM не создавались, веса/пороги JEPA не менялись, коммитов/push нет.
UI: https://forte26.vercel.app/app. API: https://154.54.100.194.sslip.io/docs.

Схема соответствует роли помощника из ТЗ: JEPA определяет риск, Qwen описывает
видимое, RAG подбирает нормативный контекст и объясняет связь. Отрицательный
класс завершается без Qwen/RAG. Неустановленность условий закона больше не
является техническим отказом. Ошибки чтения видео/моделей по-прежнему дают failed.

Отдельный `review()` возвращает признаки для человека, а не доказанное нарушение.
Поле API violation означает предусмотренные ТЗ признаки возможных нарушений.

## Почему не добавляли документы и реранкер

В baseline правильные основные нормы и обязательные пакеты уже были доступны.
Поиск занимал примерно 0,07–0,8 с. Например, для положительного эпизода пункт 20
был первым, но применение блокировали неизвестные условия. Для другого пункт 22
возвращался через карточку даже при отсутствии в top-5. Реранкер не создаст
недостающий визуальный факт. Расширение корпуса само по себе эту причину не лечит.

Отдельно на отрицательном видео свободное чтение нормы выдало ложное подозрение,
хотя JEPA дала отрицательный класс. Возврат согласованного раннего выхода убрал
такой каскад. В поиске review-режима неизвестные вопросы исключены из запросов,
но остались неизвестными при применении нормы.

## Ограничения и следующие измерения

Наблюдения Qwen и точность связи с пунктом ещё не имеют независимой оценки.
Для context_only нужно проверять описание действия и подбирать действительно
относящийся пункт, а не объявлять общий документ достаточным обоснованием.
Следующий полезный тест — слепая разметка фактов/источников на новых видео,
отдельно от бинарных меток. Реранкер проверять при ошибке порядка кандидатов;
документы добавлять при подтверждённом отсутствии нужного источника.

Три организаторских временных ориентира сопоставлены с ближайшим выходным
таймкодом в JSON. Близость времени не доказывает совпадение события и не является
полноценной метрикой локализации интервала.

Установка, режимы и откат: `takeover/datathon-forte/docs/RAG_MVP_POLICY.md`.
Исходники всех изменений находятся в рабочем дереве `takeover/datathon-forte/`.
Неприкосновенные исходные пакеты сохранены; активный overlay —
`releases/legal-rag-mvp-v1/`, сервисная политика v2 — `config/analysis-policy.json`.
