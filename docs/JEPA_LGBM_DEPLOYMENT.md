# JEPA + LightGBM: интеграция в Forte Vision

> Перенос структуры: старый JEPA-FULL убран из рабочего дерева. Текущая установка — [DEPLOYMENT.md](DEPLOYMENT.md); ниже сохранён датированный отчёт первоначального переключения.


Дата: 18.10.2026. Новый пакет владельца: `JEPA-LGBM-FULL.zip`, внутренний каталог `JEPA-LGBM`.

## Структура и выбор модели

```text
backend/detector.py               загрузчик публичного API модели
backend/pipeline.py               детектор → observer → Legal RAG
config/detector.json              активный пакет, устройство, число потоков
model_packages/jepa_lgbm/         исходники, manifest, лицензии, документация пакета
model_packages/jepa_lgbm/weights/ encoder.pt + heads.joblib, только локально
scripts/install_detector.py      установка ZIP и проверка SHA-256
tests/test_detector.py            выбор пакета, конфигурация, повреждённые веса
JEPA-FULL/                       прежний SVM-пакет, не используется рабочим pipeline
```

Исходники активного пакета сохранены без редактирования. Его `model.json` закрепляет SHA-256 62 файлов; перед десериализацией весов выполняется проверка. Не переименовывать файлы внутри пакета и не редактировать его manifest. Интеграционные изменения находятся в `backend/`, а не внутри модели.

`config/detector.json` выбирает `model_packages/jepa_lgbm`, ожидает ID `JEPA-LGBM-FULL`, CUDA и 8 CPU-потоков. Пакет импортируется по явному пути, без неоднозначного `from runtime import ...` и автоматического отката на старый SVM при ошибке. Ошибка загрузки остаётся ошибкой, а не отрицательным вердиктом.

## Архитектура

Замороженный V-JEPA2.1 ViT-L/16 на GPU → признаки двух ветвей → StandardScaler + LightGBM на CPU, без PCA.

| Ветвь | Кадров | Частота | Окно / шаг | Вес прогноза |
|---|---:|---:|---|---:|
| jepa | 16 | 2 fps | 8 / 4 с | 0.30 |
| longdense | 64 | 4 fps | 16 / 8 с | 0.70 |

Порог blend score — 0.5. Это некалиброванный score, не вероятность юридического нарушения. При отрицательном результате локализатор, Qwen и RAG не запускаются. При положительном локализатор Single-v6 возвращает максимум один примерный момент; отсутствие выраженного пика допускает `timecode_sec=null`. Observer всё равно получает обзор видео, а при наличии момента — дополнительное окно около него.

Затем прежняя схема: локальная Qwen3-VL-8B → видимые факты и кадры → Legal RAG (BM25 + BGE-M3, Qwen3-VL-4B) → возможные признаки с цитатами. Класс и score детектора не передаются в RAG как визуальные факты. Несколько конечных событий могут быть найдены observer/RAG; детектор сам не даёт тип или юридическое обоснование.

`model_versions.detector` во всех ветках API теперь равен `JEPA-LGBM-FULL`. Build ID включает код backend, конфигурацию детектора и manifest модели. Настройки Qwen и RAG при этой замене не меняются.

## Установка и воспроизводимость

Сервис использует общее окружение `.venv`; отдельный `model_packages/jepa_lgbm/install.py` для него запускать не нужно. Версии всех прежних библиотек уже совместимы. Добавлена только `lightgbm==4.6.0` в `requirements.txt`. Для Linux требуется OpenMP `libgomp.so.1` (Ubuntu: пакет `libgomp1`). На целевой VM библиотека уже установлена.

Для чистого клона подготовить окружение сервиса, установить CUDA PyTorch и `requirements.txt`, затем:

```bash
.venv/bin/python scripts/install_detector.py --archive /path/to/JEPA-LGBM-FULL.zip
.venv/bin/python scripts/install_detector.py
.venv/bin/python model_packages/jepa_lgbm/inference.py --check --device cuda
```

`bootstrap.sh` принимает `JEPA_ARCHIVE=/path/to/JEPA-LGBM-FULL.zip`; если переменная отсутствует, проверяет уже установленный пакет. Установщик не скачивает веса, не запускает обучение и отказывается затирать отличающиеся файлы. Для обновления на другой пакет нужен отдельный каталог и явная смена конфигурации.

Веса находятся вне Git. После клонирования их нужно восстановить из исходного ZIP. `scripts/package_source.py` включает исходники нового пакета, исключает `weights/`, нейросетевые веса и joblib. Перед своим коммитом можно проверить `git status` и `git diff --check`; коммит и push автоматически не выполняются.

- Worker сохраняет `PrivateNetwork=yes`; inference не обращается в сеть.

JEPA заняла 10.46 с на первом отрицательном прогоне и 3.20 с на следующем положительном; это разные видео и разные состояния прогрева, не сравнение скорости с SVM. Полная побайтовая сверка всех 66 файлов пакета с ZIP также прошла; встроенный manifest закрепляет 62 из них.

Обработка на сервере не включает передачу файла и скачивание ответа клиентом. С Windows через публичный API полное ожидание составило 25.922 с для Х-45 и 203.985 с для Х-18; отдельно вклад загрузки, опроса и скачивания не измерялся. Эта проверка не устанавливает правильность каждого наблюдения Qwen или выбранного пункта закона. UI при замене детектора не менялся; результаты прежних frontend-тестов не выдаются за повторный прогон.

## Ограничения и откат

Обе новые головы и локализатор обучены на всех 40 видео. Независимого test F1 у этой FULL-модели нет; метрики из прежнего split не являются метриками развёрнутого FULL-сервиса. Числа прежнего SVM не переносятся на LightGBM. Прогоны обучающих видео проверяют только контракт и работоспособность связки.

Перед переключением сохранена копия изменяемых файлов на VM: `data/pre-jepa-lgbm/`. Активный пакет развёрнут в `model_packages/jepa_lgbm/`; старый `JEPA-FULL/` и его веса не удалены. При необходимости остановить worker, восстановить сохранённые файлы и запустить worker. Не делать откат при активном задании без согласования с владельцем. `data/jepa-lgbm-migration/` содержит приватные журналы проверки и deployment manifest. Не включать эти каталоги в Git или source-архив.
