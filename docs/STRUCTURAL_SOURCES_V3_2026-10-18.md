## Исправление

Раньше клиентский парсер выбрасывал rule.quote, а RuleDetails показывал только
название документа, пункт и ссылку. Теперь основной пункт показывается целиком,
с переносами строк, путём главы/параграфа и связанными положениями в раскрываемом
блоке. В HTML цитата остаётся обычным текстом. Тест проверяет сохранение длинной
цитаты до последнего символа и безопасное отображение HTML-подобного текста.

Структурное разбиение не заменялось: поиск идёт по дочерним единицам, возвращает
родителя, сборщик берёт полный пункт/статью и его связи. Короткий исходный пункт
может быть короткой цитатой; это не обрезка. Проверенные длины основных цитат
реального ответа: 163, 666, 1430 символов;
каждая в точности равна тексту соответствующего родителя в снимке.

Добавлен путь вне восьми карточек: кандидаты гибридного поиска core, затем
operational. Их оценки не смешиваются. Qwen получает целые родители с контекстом,
выбирает ID пункта и ID строки требования; код берёт дословный текст источника.
Указанные моделью ID и ссылки на факты проверяются. Затем объяснение строится
по выбранному полному пункту и его связанным положениям. Если подходящего
кандидата нет, результат честно сохраняет только общий контекст документа.
Формальное insufficient не заменяется доказанным нарушением.

## Контекстное окно и квантизация

Рабочий входной лимит RAG-Qwen4B поднят с 6144 до **8192** токенов. У визуальной
Qwen8B остаётся 24576. Обе работают в BF16. 8B — число параметров, 8-bit — точность
весов; квантизация не увеличивает нативное окно сама по себе. У используемых
Qwen3-VL-4B/8B заявлено базовое окно 256K:
https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct
https://huggingface.co/Qwen/Qwen3-VL-8B-Instruct

В исходном пробном v3 были ошибки входа 6,5–6,7K > 6144, неточное переписывание
цитат и лишние отказы проверки текста. Этот пробный результат сохранён отдельно
на сервере в data/structural-sources-v3/replay-initial/. Исправление убирает
повторяющиеся названия и дублирование основного текста, сохраняет все строки,
проверяет размер готового запроса и не требует переписывать цитату моделью.
Альтернативы при нехватке бюджета пропускаются целыми родителями с записью
причины. Основной нормативный текст не режется до символов/токенов.

Первоначальный обрыв визуального JSON по таймауту — другая ранее исправленная
проблема. Его нельзя смешивать с превышением входного бюджета RAG.

семантической точности. Пункты остаются кандидатами для проверки человеком.

| Х-45, исходная отрицательная метка | done / no_violation, без Qwen/RAG | 3.401 | 49.015 |

Это обучающие ролики JEPA-FULL, не независимый test и не новый F1. Положительный
ответ проверен на 1–3 исходных JPEG на событие, точные цитаты и иерархические пути.
Эти проверки доказывают работу API и привязку к источнику, а не истинность
каждого наблюдения Qwen или применимость выбранного требования.

Визуальная конфигурация, число кадров и веса в этом изменении не уменьшались.
Предыдущие лимиты выборки и фактов сохраняются; отсутствие потерь качества от
них отдельно не доказано. Более крупная модель или квантизация требуют отдельного
сравнения на фактах/источниках с разметкой, их автоматически не включали.

Старые локальные записи UI могут уже не содержать цитату, потерянную прежним
парсером; новое отображение не восстановит её из пустого кеша. Новые ответы
сохраняют её полностью.
