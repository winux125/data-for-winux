# Forte-vision и API

Развёрнутый адрес: `https://154.54.100.194.sslip.io/app`. Базовый адрес в настройках оставляется пустым: Caddy отправляет `/api/v1/*` в FastAPI, остальное в production Vinext. `/api/client-error` принадлежит фронтенду и обрабатывается локально. Ключ вводится пользователем, не встраивается в bundle и не сохраняется в storage.

POST `/api/v1/analyze`, multipart `file`, заголовок `X-API-Key`. Ответ 202 содержит `job_id` и `status=processing`. GET `/api/v1/jobs/{job_id}` с тем же ключом опрашивается клиентом до завершения. POST автоматически не повторяется. После разрыва связи можно продолжить GET по сохранённому номеру задания.

При `done` используются только `violation` и `no_violation`. При `failed` вердикт не показывается. Коды `publication_not_allowed`, `evidence_insufficient`, `evidence_scope_unresolved`, `processing_timeout`, `worker_restarted`, `analysis_failed` имеют понятные переводы RU/KK/EN.

Событие содержит время, объяснение RAG, реальные JPEG и `rule.title`, опциональные `section` и `url`. Отсутствующие строковые поля опускаются, а не передаются как null. Нельзя подставлять демонстрационный источник или выдуманный кадр, если их нет в API. Демо-записи явно помечены.

Лимит UI и сервера согласован: 128 МиБ. Обязательный формат MOV. API также принимает MP4. Сохранённая история интерфейса не является серверной историей и исчезает вместе с сеансом; незавершённые задания сохраняют только метаданные в sessionStorage. Доказательства не покидают инфраструктуру сервиса ради анализа сторонними моделями.

В текущем исходном RAG запрещена публикация всех восьми черновых карточек. Поэтому реальный положительный юридический результат пока нельзя обещать. Успешный синтетический тест отображения событий подтверждает клиентский контракт, но не устраняет этот блокер.
