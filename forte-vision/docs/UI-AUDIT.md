# Аудит интерфейса Forte Vision

Исправления по замечаниям пользователя от 17 октября 2026 года.

## Подтверждённые причины

| Проблема | Причина | Исправление |
| --- | --- | --- |
| Лупа над полем поиска | Собственный класс `search-field` совпадал с HeroUI, где он задаёт `flex-direction: column` | Все классы рабочего пространства изолированы префиксом `fv-`; строка поиска явно располагает иконку и поле горизонтально |
| Таблица не заполняет рамку, шапка и строки имеют разные скругления | Primary-вариант HeroUI добавлял собственные отступы, фон и округление внутри панели истории | Внешняя рамка принадлежит панели, у таблицы сброшены вложенные рамки и отступы; единый фон шапки и токен границ |
| Непредсказуемый вид фильтра | Нативный select с обрезанными вариантами и без пояснений | Radix Select с клавиатурной навигацией, выбранным значением и описанием каждого варианта |
| Планшетная сетка слишком узкая | Постоянный сайдбар оставлял мало места при ширине 768–1023 px | Боковая панель скрывается в выдвижное меню до 1023 px; сетки переходят в одну колонку до того, как текст начинает сжиматься |
| Иконки уведомлений стоят выше текста | Выравнивание по верхней границе без учёта высоты строки | Иконка выровнена по первой строке через отдельную колонку grid и расчёт от line-height |
| 3D-сцена выходит за рамку | Inline min-height был больше доступной высоты контейнера | Минимальная высота снята, содержимое ограничено контейнером |
| На телефоне сцена мешает прокрутке | OrbitControls переопределял touch-action | После создания контроллера восстановлен pan-y; вращение отключено для coarse pointer |
| Нет очевидного закрытия меню | Закрытие было доступно через фон, но не внутри сайдбара | Крестик, Escape, управление фокусом; сворачивание на компьютере и раскрытие кнопкой в шапке |
| Несогласованные размеры шрифта и отступы | Повторяющиеся завершающие overrides перекрывали прежние media queries | Единые базовые правила, последовательные брейкпоинты, общие отступы и высоты заголовков |
| Рекламные заголовки мешают рабочему сценарию | Заголовки не называли действие или раздел | «Анализ кассовых операций», «Новая проверка», «Результат проверки», «Правила и источники» |

## Адаптивные состояния в коде

- От 1200 px: таблица, открытый сайдбар, две колонки результата.
- 1024–1199 px: сайдбар остаётся открытым, результат - в одну колонку; широкая таблица прокручивается внутри своей панели.
- 768–1023 px: выдвижное меню; сетка загрузки становится одноколоночной ниже 880 px.
- 641–767 px: главная, загрузка и результаты идут последовательно; таблица прокручивается внутри контейнера.
- До 640 px: вместо таблицы - карточки с подписанными метаданными, выбором, сортировкой и действиями.
- Поиск и поля аккаунта на мобильных используют 16 px; основные сенсорные действия имеют область 44 px. Длинные имена файлов и источники переносятся.
- Скроллбар прозрачен; прокрутка колесом, касанием и клавиатурой сохранена.

## Проверки выпуска

Для выпуска используются проверка TypeScript, ESLint, тесты серверной авторизации и клиента анализа, проверка diff и production-сборка. Результаты завершающих команд фиксируются отдельно; здесь не приводятся неподтверждённые числа тестов. Контракт анализа видео сохранён; авторизация аккаунта - отдельная интеграция.

## Дополнительная проверка состояний

| Состояние | Исправление в реализации |
| --- | --- |
| Выделенные записи скрылись после поиска или фильтра | Выделение сбрасывается при смене поиска/результата; таблица получает управляемый `selectedIds` и учитывает только видимые ID |
| Число событий сортировалось бы как текст | События сравниваются как числа; дата сравнивается как timestamp с безопасным fallback для демонстрационных строк |
| Пользователь удаляет одну или несколько проверок | Общий обработчик удаляет записи и выделение, закрывает удалённый результат и освобождает больше не используемые object URL |
| Удалён выбранный файл перед отправкой | Сбрасываются файл, URL, длительность, ошибка предпросмотра и значение file-input; неиспользуемый object URL отзывается |
| Метаданные MOV приходят уже после запуска запроса | Длительность дополнительно хранится в ref и при необходимости обновляется после получения metadata у плеера результата |
| Ошибка анализа произошла после ухода с формы загрузки | Сообщение сохраняется у формы и выводится уведомлением; ошибка не зависит от видимости блока загрузки |
| Просмотр события с клавиатуры или скринридером | Кнопки событий и маркеры таймлайна сообщают выбранное состояние через `aria-pressed` |
| Ширина экрана 320–380 px | Кнопка аккаунта остаётся видимой; доступ к выходу из аккаунта не исчезает вместе с второстепенными элементами шапки |
| Широкая таблица в узкой панели большого ноутбука | Подсказка горизонтальной прокрутки зависит от ширины контейнера, а не только viewport; прокручивается таблица, а не страница |
| Телефон до 640 px | Карточки сохраняют выбор всех/одной записи, сортировку и три действия; дата, длительность и события имеют подписи |
| Запуск демонстрации этапов | Условный результат явно подписан; повтор не отправляет видео и не вызывает модель |
| Реальная обработка | Схема показывает передачу и доступный статус сервера; промежуточные этапы модели не выдумываются |

## Лендинг и аккаунт

Лендинг, формы и рабочее пространство используют раздельные префиксы классов. Декоративная схема и условные события подписаны; схема не выдаётся за кадр исходного видео. На страницах аккаунта есть отдельные формы входа, регистрации и восстановления, сообщения об ошибках и показ пароля.

Продуктовый вход на `/app` использует Supabase при заданной конфигурации. `/demo` отделён от него и сохраняет нативную проверку доступа Sites. Ни демонстрационный переход, ни клиентский флаг не создают подтверждённый аккаунт продукта. Подробности и ограничения настройки писем - в [AUTH.md](AUTH.md).

## Границы проверки

Перечисленные исправления подтверждены чтением исходников и стилей установленных библиотек. В доступной среде нет браузерного инструмента для визуальной проверки Sites. Не выполнялись сравнение скриншотов, измерение реальной геометрии DOM, проверка на физических устройствах или полный цикл email-регистрации. Наличие media/container queries не заменяет такую проверку.


## Темы и новые элементы интерфейса

Добавлены системная, светлая и тёмная темы для лендинга, авторизации, рабочего пространства, таблиц, меню и страниц 404/данных. Применение темы до гидратации проверяется отдельными тестами, включая недоступность localStorage. Радиокнопки темы в меню аккаунта участвуют в клавиатурной навигации Radix.

Футер, стеклянные папки и ASCII-переход адаптированы из предоставленных фрагментов под Forte. Папки используют существующие записи и открывают те же результаты, что таблица. Список при раскрытии не ограничен тремя визуальными листами. Анимация вступления не скрывает серверный контент без JavaScript и отключается при reduced motion.

Уведомление о cookies описывает только технические сессии и настройки. Кнопка в футере открывает его повторно. Страница `/privacy` не заменяет политику оператора сервиса. Браузерная визуальная проверка в управляемом окружении остаётся недоступна; выполнены проверки кода и серверного вывода.
