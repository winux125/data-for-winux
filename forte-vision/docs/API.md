# Подключение сервиса анализа

Фронтенд не содержит модель и не имитирует результат в режиме подключения. Интеграция находится в `lib/analysis.ts` и работает в браузере. Демо интерфейса отделено от реального анализа.

## Запросы

1. `POST {baseUrl}/api/v1/analyze` - `multipart/form-data`, поле `file` с записью `.mov`. Не задавайте `Content-Type` вручную: браузер добавляет boundary.
2. `GET {baseUrl}/api/v1/jobs/{job_id}` - опрос раз в 1,5 секунды до `done` либо `failed`.

В обоих запросах передаётся `X-API-Key`, если ключ заполнен. Полный лимит ожидания клиента, включая загрузку, - 5 минут. Отмена прерывает загрузку, запросы и опрос на клиенте. Для остановки задания на сервере понадобится отдельный endpoint, которого в текущем контракте нет.

Запись истории создаётся до отправки файла и получает серверный `job_id` при первом успешном ответе. При переходе между разделами запросы продолжаются. После отмены, тайм-аута или исчерпания повторов известный `job_id` позволяет выполнить GET-only возобновление, без повторной загрузки.

Сетевой сбой, HTTP 408/429/5xx в GET повторяются до трёх раз с задержками 1,5 / 3 / 6 секунд. Успешный ответ сбрасывает счётчик. Ошибки 401/403, некорректный JSON и нарушение контракта требуют действий пользователя; автоматически не повторяются. POST никогда не повторяется автоматически. Каждый запуск/возобновление имеет общий лимит пять минут.

Метаданные незавершённых заданий сохраняются в sessionStorage (до 20 записей). Ключ, файлы, blob-URL, результаты и кадры не сохраняются. После перезагрузки подключение и ожидание возобновляются вручную на том же сервере. Для просмотра восстановленного результата пользователь добавляет исходный MOV локально, не отправляя его повторно.

Ответ создания задания, HTTP 200 или 202:

```json
{ "job_id": "job-123" }
```

При создании задания гарантирован только `job_id`. Сервер также может передать `"status": "processing"`; если статус не указан, клиент начинает опрос. Во всех ответах `GET` поле `status` обязательно.

Ответ обработки:

```json
{ "job_id": "job-123", "status": "processing", "progress": 47 }
```

`progress` необязателен; это процент от 0 до 100, рассчитанный сервером. Процент передачи файла в интерфейсе берётся из реальных событий загрузки XHR и не является прогрессом модели.

Завершённый результат:

```json
{
  "job_id": "job-123",
  "status": "done",
  "verdict": "violation",
  "violations": [
    {
      "id": "event-1",
      "type": "Название категории из модели",
      "timecode_sec": 12.5,
      "description": "Описание наблюдаемого действия, подготовленное сервисом анализа.",
      "evidence_frames": [
        { "timestamp_sec": 12.5, "image_base64": "ПОЛНЫЙ_BASE64_JPEG_ИЛИ_PNG" }
      ],
      "rule": {
        "title": "Реальное название нормативного источника",
        "section": "Номер применимого пункта",
        "url": "https://example.kz/actual-source"
      }
    }
  ]
}
```

Строки в примере - обозначения полей, не готовые доказательства или нормативные ссылки. Отправляйте полные реальные данные. `image_base64` принимает raw base64 либо `data:image/jpeg;base64,...` / `data:image/png;base64,...`; SVG и произвольные URL не отображаются; для такого кадра остаётся заглушка. Для события по кейсу ожидается 1–3 кадра. Пустой массив остаётся видимым как отсутствие кадров; клиент не создаёт доказательства самостоятельно.

Для результата без событий обязательны `"verdict": "no_violation"` и `"violations": []`. Для `violation` список должен содержать минимум одно событие. `timecode_sec` и `timestamp_sec` - неотрицательные числа в секундах от начала записи.

Клиент сравнивает время события и кадров с реальной длительностью из метаданных видео. Время за пределами записи остаётся видимым с предупреждением; фрагмент для такого события не создаётся. Неизвестная длительность не подменяется предполагаемой. Значения NaN, Infinity и отрицательное время отклоняются как нарушение контракта.

`id` и `rule` необязательны в API. В `rule` обязательным становится `title`; `section` и `url` можно опустить. Нормативный источник нужен для полноценного результата по кейсу; если сервер его не передал, интерфейс показывает отсутствие источника и ничего не выдумывает. Применимость нормативных актов и их содержание должны проверяться командой отдельно.

Ошибка обработки:

```json
{ "job_id": "job-123", "status": "failed", "error": "Причина сбоя" }
```

## Адрес, CORS и ключ

Пустой `baseUrl` означает текущий origin сайта. Внешний адрес должен использовать HTTPS; HTTP допускается только для `localhost`, `*.localhost`, `127.x.x.x` и `[::1]`. `localhost` в браузере обозначает компьютер пользователя, а не сервер размещённого сайта. HTTPS-страница может блокировать HTTP из-за mixed content; доступ к локальной сети также может требовать разрешения браузера.

Для внешнего сервиса настройте CORS на точный origin фронтенда: разрешите методы `POST`, `GET`, `OPTIONS` и заголовок `X-API-Key`. Preflight `OPTIONS` не должен требовать ключ. Не публикуйте общий секрет в исходниках, переменных `NEXT_PUBLIC_*`, URL или браузерном хранилище. В текущем UI введённый ключ хранится только в памяти вкладки и очищается при перезагрузке.

Пользовательская авторизация удалена: фронтенд доступен без аккаунта. В текущей версии запросы с `X-API-Key` идут напрямую в выбранный API; ключ не записывается в исходники или браузерное хранилище. Ключи и авторизация самого сервера анализа определяются контрактом жюри. Серверного proxy к модели в этой версии нет.

## Вызов из React

```ts
const controller = new AbortController();
const result = await analyzeVideo(file, { baseUrl, apiKey }, {
  signal: controller.signal,
  onUploadProgress: setUploadProgress,
  onStatus: setJob,
});
// controller.abort() прекращает ожидание.
```

Клиент проверяет структуру итогового результата и отклоняет отсутствующий вердикт, неизвестные статусы и противоречивые списки событий. Ошибка изображения не отклоняет событие: вместо кадра показывается заглушка, описание и источник остаются доступными. Транспортные ошибки, HTTP 401/403, 413, 415, 429, отмена и тайм-аут имеют понятные сообщения на русском.


## Ограничения изображений и отображение медиа

- До 3 кадров на событие. Количество дополнительных кадров показывается отдельно в `omitted_evidence_frames`.
- До 2 МиБ декодированного бинарного файла на кадр; до 8 МиБ таких данных во всём результате.
- PNG/JPEG: сторона до 4096 px, площадь до 8 388 608 пикселей. Размеры проверяются по заголовку до создания изображения и по `naturalWidth`/`naturalHeight` после загрузки. Ошибки `img` и `decode()` дают заглушку, увеличение доступно только после успешного декодирования.
- Ответ API ограничен 16 МиБ. Поток GET и загрузка ответа XHR прерываются при превышении лимита. Слишком большой целый JSON не разбирается; нужно уменьшить payload на сервере. Изображение, превышающее свой лимит внутри допустимого ответа, не мешает показать описание события.
- Недоступные изображения удаляются из клиентской копии результата (`image_base64: ""`, локальное поле `image_issue`: `invalid`, `size`, `dimensions` или `budget`). Эти служебные поля могут присутствовать в JSON-экспорте.
- `processing.progress` от 0 до 100 показывается в карточке задания, на странице загрузки и в общей панели. Ноль — реальное значение; при отсутствии процента показывается неопределённое ожидание. Во время восстановления связи имеющееся значение подписано как последний прогресс.
- Видеоплеер становится готовым по `canplay`, а не только по метаданным. При ошибке скрываются native controls и действия воспроизведения, снимается режим фрагмента; доступен переход к кадрам/описанию. Успешный `play()` и поддержка конкретного кодека зависят от браузера.
- Таймлайн ограничен тремя строками. Плотные пересекающиеся маркеры объединяются с сохранением исходных индексов. Кнопка группы открывает список по 20 событий с пагинацией и областью прокрутки до 360 px; ни одно событие не отбрасывается.


## Состояние параметров и соединения

Параметры API находятся в памяти страницы отдельно от статуса соединения. Сохранение параметров не отправляет сетевой запрос. В текущем контракте нет endpoint проверки здоровья: фронтенд не выдумывает такой запрос и не создаёт задания для проверки связи.

При первом настоящем запросе появляется «Проверка связи». «Связь подтверждена» означает получение и валидацию реального ответа POST/GET; синтетическое локальное состояние возобновления её не подтверждает. Указывается время последнего успешного ответа. Через 60 секунд без нового успешного ответа статус становится «Ответ был ранее»; фоновые запросы ради зелёного индикатора не отправляются.

Сетевой сбой/тайм-аут, HTTP 401/403 и ошибка формата ответа имеют отдельные состояния. При повторе статуса показывается восстановление связи. `status: failed` в валидном ответе означает неудачу задания, а не отсутствие соединения. Изменение адреса или ключа сбрасывает подтверждение. Ответы старого подключения не могут подтвердить новое.

## История просмотра и Undo

Навигация имеет клиентские адреса `/app#workspace/{section}`, `/app#workspace/checks/{local_id}` и `/app#workspace/checks/{local_id}/event/{number}`. В fragment нет ключа, имени файла, содержимого видео, кадров или результата. `history.state` содержит только собственные данные раздела/ID/экрана/позиции/границ фрагмента и сохраняет служебные поля роутера. Обновление времени заменяет текущую запись, переходы добавляют запись. Browser Back/Forward восстанавливают состояние без повторного POST. Просмотр после перехода остаётся на паузе.

Завершённые результаты по-прежнему живут в памяти вкладки. Открытие адреса завершённой проверки после перезагрузки не восстанавливает потерянные данные: вместо выдуманного результата показывается недоступность копии. Метаданные незавершённых заданий восстанавливаются отдельно, как описано выше.

Удаление из списка удерживает единственную клиентскую копию ещё 10 секунд. Undo возвращает исходные объекты результата и URL видео, порядок и выделение. Несколько удалений в незавершённом окне объединяются; новый срок относится ко всей группе. Новые загрузки при восстановлении сохраняются. После истечения срока blob URL освобождаются, если на них больше нет ссылок в списке/форме. Активное задание удалить нельзя. Отмена действует в текущем сеансе и не отправляет запросы удаления на сервер. Перезагрузка закрывает возможность Undo.
