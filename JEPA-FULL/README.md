# JEPA-FULL — финальная модель, CPU и NVIDIA GPU

Передайте человеку **один файл `JEPA-FULL.zip`**. Внутри готовые веса, код, установщик и эта инструкция. Репозиторий, датасет, аккаунт Brev, API-ключи и обучение не нужны. Интернет нужен только для первой установки Python-зависимостей; затем инференс работает локально без сети.

**FULL:** обе головы PCA/SVM и локализатор заново обучены на **всех 40 уникальных видео** (21 нарушение, 19 без нарушения; 22 точки событий). Бывший test включён в обучение. Encoder JEPA заморожен, как и в выбранном бейзлайне. Параметры и веса бленда сохранены. Независимой оценки этой FULL-модели нет.

## Быстрый старт

1. Распакуйте ZIP. Откройте терминал в появившейся папке `JEPA-FULL`.
2. Нужен установленный **64-битный Python 3.10–3.13**; рекомендуем 3.11.
3. Установите зависимости и запустите видео:

Linux / macOS:

```bash
python3 install.py
python3 run.py --video "/path/to/video.mov" --out result.json
```

Windows PowerShell / CMD:

```powershell
py -3.11 install.py
py -3.11 run.py --video "C:\videos\video.mov" --out result.json
```

Если используется другая поддерживаемая версия Python, замените `py -3.11` на её команду. Активация окружения не требуется: установщик создаёт `.venv`, а `run.py` сам выбирает Python из неё. В терминале выводится JSON; `--out` сохраняет тот же JSON в файл.

Установщик по умолчанию выбирает CUDA-сборку при обнаружении NVIDIA GPU через `nvidia-smi`; иначе CPU-сборку. Можно выбрать явно:

```bash
python3 install.py --device cpu
python3 install.py --device cuda
```

Для NVIDIA GPU нужен установленный совместимый драйвер. Установщик ставит CUDA 12.6 wheels; CUDA Toolkit отдельно не требуется для этих готовых wheels. На macOS устанавливается сборка PyTorch из PyPI и используется CPU; Apple MPS в этом релизе не задействован. Команды CPU/CUDA для зафиксированного PyTorch взяты из [официальной инструкции PyTorch 2.9.1](https://pytorch.org/get-started/previous-versions/#v2-9-1).

Установщик создаёт окружение через стандартный `venv`; если в нём нет pip, используется включённый официальный [get-pip.py от PyPA](https://pip.pypa.io/en/stable/installation/#get-pip-py). Если в самой установке Python отсутствует модуль `venv`, на Ubuntu установите `python3-venv`. FFmpeg/FFprobe отдельно ставить не нужно: метаданные читает PyAV с включёнными в wheel библиотеками FFmpeg, кадры декодирует OpenCV. [Установка PyAV](https://pypi.org/project/av/16.0.1/).

## Выбор устройства и проверка

```bash
python3 run.py --check
python3 run.py --video video.mov --device cpu --threads 4 --out cpu-result.json
python3 run.py --video video.mov --device cuda --out gpu-result.json
```

По умолчанию `--device auto`: доступная CUDA → GPU, иначе CPU. `--device cuda` выдаёт явную ошибку, если CUDA недоступна. CPU работает в FP32, GPU — в BF16 при поддержке, иначе FP32. `--threads` задаёт число потоков PyTorch, по умолчанию 4. На CPU с меньшим числом ядер попробуйте 1–2. Смена CPU-потоков и аппаратной платформы может давать небольшие численные отличия.

`--check` проверяет SHA-256 весов/кода, библиотеки и выбранное устройство. Не редактируйте содержимое пакета, иначе контроль целостности сообщит об изменении. Для обновления переносите целиком новый релиз, а не отдельный файл весов.

Если запускаете в уже подготовленном окружении, можно использовать `python inference.py` с теми же аргументами. Версия `scikit-learn==1.7.2` обязательна для сохранённых голов.

## Результат

Сокращённый пример нарушения:

```json
{
  "status": "ok",
  "label": 1,
  "label_name": "нарушение",
  "violation_detected": true,
  "score": 0.623,
  "timecode_sec": 10.462,
  "timecode": "00:00:10.462",
  "timestamp_status": "estimated",
  "events": [{"timecode_sec": 10.462, "timecode": "00:00:10.462"}]
}
```

Без нарушения:

```json
{
  "status": "ok",
  "label": 0,
  "label_name": "без нарушения",
  "violation_detected": false,
  "score": 0.312,
  "timecode_sec": null,
  "timecode": null,
  "timestamp_status": "not_applicable",
  "events": []
}
```

Порог фиксирован: `score >= 0.5` → нарушение. `score` — среднее sigmoid двух SVM margins, **не калиброванная вероятность**. При отрицательном прогнозе локализатор не запускается и таймкодов нет. При положительном выдаётся максимум один момент. Если временной профиль плоский, метка остаётся 1, но таймкод `null`, `events=[]`, `timestamp_status="uncertain"`.

В полном JSON также есть длительность ролика, фактическое устройство, точность encoder, число потоков, время обработки и SHA-256 манифеста модели. Ошибки идут в stderr, ненулевой код завершения — 1; ошибка чтения видео не превращается в метку «без нарушения».

## CPU, GPU и проверка

Поддержаны те же `--device auto|cpu|cuda` и `--threads`. CPU-прогоны FULL не запускались по просьбе владельца проекта. У исходной модели с той же архитектурой 16.5 с видео заняли около 11 минут на CPU AMD EPYC с 4 потоками и около 13 с на L40S, включая загрузку; это справочные измерения исходной модели, не отдельный бенчмарк FULL. Для быстрого инференса рекомендуется GPU. CPU использует FP32, GPU — BF16 при поддержке; score и метка около порога могут различаться. Подтверждённая аппаратная платформа пакета — Linux x86-64; Windows/macOS учитываются установщиком, но отдельно не проверены.

Для коротких видео желательно 8 ГБ свободной RAM или больше; расход растёт с длиной видео. Замороженный encoder, разрешение 384 и число кадров не сокращены. [Проверки FULL](FULL_VALIDATION.json), [протокол обучения](TRAINING.json).

## Python API

Запускайте из каталога пакета или добавьте этот каталог в `sys.path`. Загружайте модель один раз для последовательной обработки нескольких видео:

```python
from runtime import JepaModel

model = JepaModel(device="auto", threads=4)
result = model.predict("video.mov")
print(result["label"], result["timecode"])
second = model.predict("another.mov")
```

Один объект используйте последовательно, не одновременно из нескольких потоков.

## Модель и оценка качества

Один замороженный V-JEPA2.1 ViT-L, два режима 8 с / 16 кадров и 16 с / 64 кадра, PCA + SVM с весами 50/50. Классификаторы, их scaler/PCA и appearance/motion rankers локализатора single-v6 переобучены с нуля на всех доступных уникальных видео. Локализатор использует 21 положительное видео и 22 размеченные точки. Гиперпараметры взяты из ранее выбранного варианта, без нового подбора.

**У FULL нет отдельного train/test split: все 40 видео — train.** Прежние F1 0.8571 и показатели таймкодов относились к исходной модели, обученной на 28 видео, и не являются результатами JEPA-FULL. Проверка на тех же 40 видео не будет независимой оценкой качества. Нужны новые размеченные видео для такого теста.

Таймкод остаётся приблизительным, не границами события. Если нарушения нет — таймкод null; если положительный временной профиль плоский — статус uncertain без придуманной точки. Тип нарушения и юридическое объяснение модель не выдаёт.

## Содержимое

- `install.py` — установка в изолированную `.venv`, `run.py` — запуск без активации окружения.
- `inference.py`, `runtime.py` — CLI и Python API.
- `weights/encoder.pt`, `weights/heads.joblib` — все готовые веса.
- `model.json` — параметры и SHA-256; `TRAINING.json`, `FULL_VALIDATION.json` — обучение и проверки FULL.
- `forte_vlm/`, `vendor/vjepa2/` — необходимые функции и исходник encoder с лицензиями Meta.
- `examples/` — JSON-примеры, без исходных видео и датасета.

Исходный encoder commit `204698b45b3712590f06245fbfba32d3be539812`. Из исходного checkpoint сохранены только `ema_encoder` тензоры без изменения значений. Все исходные SHA-256 находятся в `model.json`. Формат PyTorch + sklearn сохраняет весь проверенный видеопайплайн; конвертация в ONNX не требуется для CPU. Лицензии исходника находятся в `vendor/vjepa2/`.
